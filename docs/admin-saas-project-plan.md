# GYUTRON Operations — 项目计划与发布约束

启动：2026-11-03 13:50，新加坡时间。计划持续推进至 17:50，期间完成实现、交叉检查、发布与巡检。

## 1. 产品目标

将 `/admin` 从表单记录查看器升级为工业企业的销售与服务运营工作台。首个版本以真实业务闭环为验收目标：官网询盘进入收件箱，转换客户与商机，安排跟进任务，记录活动，并由仪表盘、筛选、导出与审计支持日常管理。

扩展交付工业报价闭环：单币种明细与手工商业金额、草稿保存、签发冻结、修订链、外部结果内部记录、四语打印与浏览器另存PDF。客户文档与内部反馈分离，历史签发内容不随CRM或品牌设置变化。

产品名称暂定 **GYUTRON Operations**。视觉沿用官网硬朗工业体系：无圆角、深炭导航、灰白工作区、两种品牌按钮 token、克制文案、密集且清晰的信息层次。

## 3. 对标方式与技术选择

对标 Salesforce 的客户与商机关系、HubSpot 的记录和活动、Linear 的紧凑操作、Odoo/ERPNext 的业务领域边界。具体来源与许可结论记录在 `admin-saas-research.md`。

保留已运行的 Worker/D1 架构，以标准 JavaScript、Web API 和 SQL 实现域层及 API。前端为独立管理工作台，不引入第二套生产打包链。开源依赖按实际许可证声明；Cloudflare 托管服务不宣称为可完全自托管的开源产品。

首版采用每客户独立 Worker + D1 的部署隔离模型。商业交付可以使用独立实例；共享库多租户、自助订阅计费、财务总账及库存会计必须在相应实现和验收完成后才可宣称具备。

## 5. 数据与安全验收

- 所有业务数据从数据库读取，空记录显示空态；服务失败显示错误，不能显示伪造的零值。
- 角色权限在服务端验证，禁用用户和退出登录能够失效会话。
- 所有写入限制同源，验证内容和字段长度；SQL 参数化。
- 修改携带版本号，并发冲突给出明确反馈。
- 归档可恢复，不提供未经授权的永久销毁。
- 业务变更与审计在同一数据库事务中提交。
- 导出使用显式字段、保留过滤条件、防止电子表格公式注入，并明确导出范围。
- 不同币种分别统计，商机金额不得标成营收。
- 超过JavaScript安全整数的聚合使用精确字符串与BigInt格式化，不能静默四舍五入。
- 报价签发快照包含商业正文与业务日期；内部结果备注不进入客户打印。
- 增量迁移前备份，保留生产官网现有表单、索引路径和独立 Shop 边界。

## 6. 发布与验收证据

必须运行仓库规定的 Astro build / verify:all、agent:check、deploy:check、Worker dry-run、平台 smoke，以及新增权限和业务 API 验证。浏览器覆盖桌面、平板、320–430px 手机、键盘、空态、失败态、创建/编辑/筛选/分页/归档恢复。

生产发布使用已核实的既有部署链路；数据库仅应用审查后的增量迁移。上线必须验证实际页面版本、API鉴权和关键业务读取，并记录 Cloudflare 版本/提交、CI、截图与回滚方式。
