# Deployment — gyutron.com

## Model

- **Cloudflare Worker serves the committed `public/` directory.** Cloudflare does **not** run a build.
- **Push to `main` → Cloudflare auto-deploys.** So `public/` must contain the built site, and it is
  git-tracked.
- `wrangler.toml`: `main = src/worker.mjs`, `[assets] directory = "./public"`, `run_worker_first = true`.
- `src/worker.mjs` routes: `POST /api/contact` → `contact-handler.mjs` (Resend email);
  `shop.gyutron.com/*` → rewrites to `/shop/` (out of scope); everything else → `env.ASSETS.fetch`.

## Local dev

```
cd astro
npm ci
npm run dev       # http://localhost:4321
npm run build     # outputs astro/dist (also the missing-i18n-key gate)
npm run preview   # serve the build
```

## Deploy procedure (every change to a rendered page)

1. Edit `astro/src/**`.
2. `cd astro && npm run build` (a missing i18n key throws — that's the gate).
3. **Sync the changed build output into the committed `public/`**: copy the changed
   `astro/dist/<file>` to the same path under `public/` (e.g. `index.html`, `de/index.html`,
   `ja/index.html`, changed `.css`, `_astro/…`). Only `public/` is deployed. **Never touch the
   `shop` subtrees.**
4. Commit `astro/` **and** `public/` with an explicit path list, then push.

Use the cross-platform read-only comparison from the repository root before choosing files to sync:

```bash
npm run deploy:diff
```

The tracked Turnstile site-key fallback makes builds deterministic. `npm run verify:turnstile` must
pass; never deploy form HTML without the widget while the Worker secret may be active.

It excludes `shop/`, `de/shop/`, and `ja/shop/`, hashes file bytes, and never copies or deletes.

`public/` intentionally contains production assets that are not emitted by the current Astro build.
As of 2026-08-07 there are 131 non-Shop public-only files, and built pages still reference at least some
of them. Therefore:

- never mirror-delete or make `public/` equal to `astro/dist/` by removing public-only files;
- `astro preview` is not fully deploy-equivalent and may show a 404 for a production-only asset;
- after selective sync, use `npx wrangler dev` or the real site for complete asset/routing acceptance.

CSS cache keys are generated by `astro/src/lib/cssVersion.ts` from LF-normalized stylesheet text. Do
not revert to raw-byte hashing: Windows/Linux working-tree line endings would generate different
`?v=` values and break the cross-platform deploy-sync gate.

> Pure scaffolding changes (new files under `src/config`, `src/types`, `src/lib`, `src/data`, `docs/`,
> `.env.example`) that **no page imports** do not change `astro/dist`, so there is nothing to sync to
> `public/` and the live site is unaffected.

## Concurrency guard (multiple agents may share this checkout)

Before **any** edit and immediately before **every** push:

```powershell
git status -sb
git fetch origin
git rev-parse HEAD
git rev-parse origin/main
npm run agent:status
```

Do not stop another agent process, reset its files, or pull/rebase through a dirty worktree. If the tree
is dirty, identify and preserve ownership first. If local and remote differ, inspect the commits and
synchronize safely; never force-push. Update `HANDOFF.md`, run `npm run agent:check`, commit with
explicit paths (`git add -- astro/ public/ docs/ …`), and never use a blind `git add -A`.

## Never run the legacy generator

`npm run i18n:build` / `i18n:sync` / `python tools/generate_localized_site.py` regenerate the **old**
HTML into `public/` and **clobber the Astro site**. See TROUBLESHOOTING.md.
