# 工作台测试模式维护

测试模式用于向客户演示产品，也供员工试用工作台流程。数据为浏览器内存中的虚构记录；它不向生产 D1/R2 写入、不调用外部模型，也不把示例业务数据种入真实数据库。此页描述实现合同，发布结果以对应检查报告为准。

## 隔离入口

- 进入/退出使用完整页面重载，切换前先处理正在执行的操作和未保存表单。新页面重新创建控制器与通知轮询，旧控制器不在两种模式间复用。
- `?test=1` 为显式测试入口，浏览器会话偏好可保存开关状态；两侧切换都清除旧记录深链参数，避免把虚构 ID 带入真实模式。
- 测试入口必须在首个业务 API 请求之前确定。演示模块加载或执行失败时显示错误，绝不能退回真实 API。
- `src/admin/demo-client.mjs` 导出 `DEMO_CLIENT`，其实际浏览器 ESM 导出 `createDemoWorkspace({now,language})`。返回 `{modules, api, reset, exportData, printQuote}`，所有状态只存于该实例内存。
- `api(path, options)` 采用与实际控制器一致的 `data/meta` JSON 合同；未知路径或方法失败关闭，错误带 `status/code`。输入与输出不得暴露可修改的内部引用。

## 下载、打印与外链

仅替换 central `api()` 仍不够。以下入口不能保留指向真实后台的 `href` 或原生提交：

| 入口 | 演示行为 |
|---|---|
| CRM CSV `/admin/api/export` | 由 `exportData()` 生成本地字符串并下载 |
| 导入错误 CSV | 同上，内容来自当前演示批次 |
| 备份 SQL / JSON | 本地虚构制品，必须注明演示；不得下载真实 R2 对象 |
| 报价 `/admin/quotes/:id/print` | 当前界面克隆正在展示的 `.quote-document` 到本地 Blob，附自身样式与 DEMO 声明，不访问真实报价打印路由；适配器另提供纯本地 `printQuote()` 辅助合同 |
| 旧订单处理页 | 本地虚构订单呈现，不能跳到真实旧页面 |
| 本地 CSV / 文档采集器 | 测试模式中禁用，不能提供指向真实实例的执行命令 |
| `/admin/logout` 表单 | 不提交真实退出；引导退出测试模式 |
| 模型测试、商业许可、备份验证 | 仅明确的演示结果或禁用；不得宣称真实外呼、签名激活或 R2 恢复已经执行 |

不能仅拦截普通左键点击：中键、键盘、新标签和复制链接同样可能绕过。演示模式应在渲染阶段移除这些真实后台 URL；捕获阶段的链接拦截作为补充。

## 与新功能同步

本轮经营工作台包含业务概览、商机阶段、网站请求三组指标，以及报价请求、销售询盘、商机、任务、报价单五类工作清单。`dashboard.intake` 使用与 Live 相同的 `{resource,fresh,total}` 合同，并由当前内存中的 intake 记录计算。清单沿用原始 API 的资源、状态和数量范围，报价未加载的数量显示“—”。RFQ 的具体需求、数量和采购时间来自既有 schema 字段；演示内容只补充在 Test 数据中。国家图标只根据已记录国家展示；展示名称变化不能合并筛选键。

验证时切换三组指标和五类清单，打开任意 RFQ/客户/商机/报价详情，并完成一个演示任务；检查原有页面仍可到达、计数来自响应、货币分别显示、只读角色无编辑按钮、切换清单后的旧响应不覆盖新内容。所有模拟网络/导出仍经同一个 fail-closed 适配器。

2026-11-04 的界面版本仍使用同一套真实控制器。总览的未关闭商机、逾期任务入口使用生产和
演示两端已有的筛选条件；“查看全部任务”“打开收件箱”明确表示导航，不能把所有记录当成该指标的精确钻取。
销售漏斗和经营趋势均从有关联的虚构商机、订单计算，不能在图表组件内制造随机波形或增长率。
默认多币种金额显示币种数量，展开后逐币种显示精确金额，选择币种后只显示该币种；禁止跨币种相加。
每日自动化按演示工作区的 Asia/Singapore 日历计算下一次执行时间，编辑、暂停和恢复同样遵守该计划。
演示审计记录的实体类型和编号必须指向对应类型的实际虚构记录。

每次新增导航模块、API 分支、动态弹层或直链下载时，同时完成：

1. 更新演示适配器的 API 合同与有关联的虚构记录，含可见的成功、空、失败或待处理状态。
2. 更新 `modules` 与测试中的模块请求合同。`scripts/test-admin-demo.mjs` 从真实 shell 的 `data-nav` 集合检查覆盖，不允许新增模块悄悄漏掉演示。
3. 增加能失败的行为断言，验证筛选/分页、写入后刷新、版本冲突和关联关系；不能只把相同字段写两遍作为测试。
4. 检查新入口是否绕过 central `api()`，尤其 `<a href>`、`window.open`、文件下载、采集器指令和原生表单。
5. 验证中文与 English 的标签及生成内容；用户输入的业务文字不自动翻译。

```powershell
node scripts/test-admin-demo.mjs
```

## 数据与商业边界

演示许可证、模型使用量、自动化历史、报表、备份与健康指标均为虚构状态。它们不得被表述为该客户已购买的权益、真实账单、SLA、实际模型响应或已完成的生产恢复。刷新/重置会丢弃内存修改；不同演示实例互不共享修改。退出测试后重新读取真实 API，真实业务数据不因此被替换。


## 构建后的完整启动门槛

`.9`曾在真实Wrangler打包时将私有`__name`带入`Function.toString()`序列化内容，导致初始化前错误并永久停留Loading。规范辅助函数由`generate-admin-test-mode.mjs`在打包前生成浏览器字符串；修改规范代码后须重新生成，并通过`--check`一致性门槛。

任何启动/辅助函数/构建改动必须运行`npm run check:admin-startup`。该测试用真实Wrangler产物完整执行初始化与首屏，覆盖中英及两种模式，还包含缺失函数/跳过初始化的负向控制。只验证源码语法、资源哈希或演示适配器不足以证明工作台能启动。可用`--compiled-worker`复用明确的真实构建，或`--workspace-file`执行已独立核对哈希的线上主脚本；这些VM检查仍不替代像素和无障碍验收。
